## Auth and API key handling
- Session/user auth (web UI): /root/code/router/router_new/internal/transport/http/middleware/auth.go
  - UserAuth/AdminAuth/RootAuth use sessions or access token (access token in user table).
- TokenAuth (API key auth) supports three paths:
  1) wallet JWT (VerifyWalletJWT) -> auto pick first available token
  2) UCAN token (common.IsUcanToken + VerifyUcanInvocation)
  3) sk- token (ValidateUserToken)
  Path: /root/code/router/router_new/internal/transport/http/middleware/auth.go
- API key format:
  - Stored key is 48 chars (random + UUID) generated by /root/code/router/router_new/common/random/main.go
  - Client can send: Authorization: Bearer sk-<key>
  - Admins can pin a channel: sk-<key>-<channelId> (TokenAuth sets SpecificChannelId)
- Token restrictions:
  - Subnet check: Token.Subnet, validated by common/network
  - Model allowlist per token: Token.Models

## Channel data model and provider selection
- Channel model + fields: /root/code/router/router_new/internal/admin/model/channel.go
  - Key: upstream secret (used as Authorization by default)
  - BaseURL: override upstream base URL
  - Group, Models: comma-separated lists
  - ModelMapping: JSON map for model name rewrite
  - Config: JSON (ChannelConfig) for provider-specific fields (ak/sk/api_version/etc)
  - ModelRatio / CompletionRatio: JSON overrides for billing ratios
- Channel repository: /root/code/router/router_new/internal/admin/repository/channel/repository.go
- Channel endpoints (admin): /root/code/router/router_new/internal/admin/controller/channel/handler.go
