# Channel 探查说明（Qingyun Top Key 模型可用性）

## 背景与目标
- 需求来源：老板的最新 issue 中包含“渠道支持模型通过渠道获取，特殊情况可以填和改”。
- 当前问题：不同供应商是否支持“使用 key 拉取可用模型列表”并不统一，需要先探查。
- 本目录用于记录对 **Qingyun Top** 渠道的 key 能否拉取模型、模型列表接口形式、鉴权方式等。

## 你要做的探查重点（教师指导）
1) **是否支持模型列表接口**
   - 能否通过 key 拉取模型清单（如 /v1/models 或其他路径）。
2) **鉴权方式**
   - 是否使用 Authorization: Bearer <key>
   - 是否需要额外 header / 参数。
3) **返回结构**
   - 返回是否是标准 OpenAI 兼容格式（data[]/id）
   - 是否需要适配/转换。
4) **失败行为**
   - 无权限 / key 无效 / 未开通时的响应码与提示。

## 约束与注意事项（指挥官）
- 必须在仓库根目录 /root/code/router/router_new 下工作，避免 .env 不加载导致误连 SQLite。
- 不要改动 .env 或 SQL_DSN；保持线上 PG 配置不变。
- 只做“探查与记录”，不要改业务逻辑。
- 记录要能直接反哺后续实现“渠道自动拉模型”功能。

## 建议输出格式
- 记录可用接口：URL、method、headers、示例响应。
- 结论：能拉 / 不能拉 / 需额外权限。
- 若不能拉：给出可行替代（静态模型列表 + 手动编辑）。
